# Enterprise RAG Learning Project Portfolio

一个以“可解释、可评测、可更新、可回退”为目标的企业级 RAG 学习项目。它不把作品集重点放在单次回答效果，而是展示如何定位 badcase、建立独立验证、控制实验发布，并把安全和索引更新变成可重复门槛。

## 项目结论

- 54 份可追踪文档构建为 942 个结构化 chunks，使用 bge-m3、Chroma 和 BM25。
- direct 是稳定默认；conservative planned v3 通过 32 题独立 holdout 的无退化门槛，进入 Web 手动实验模式。
- 答案链路区分检索证据、短期记忆和长期记忆，并执行引用、忠实度、覆盖和安全审计。
- 索引以不可变版本构建，通过结构、冻结检索和完整测试后原子启用，可一步回滚。
- 提示注入、凭据索取、跨用户记忆和知识库外实时问题在检索与模型前处理。
- 本地与 GitHub Actions 使用统一质量入口；当前 139 项测试和 8 项安全冻结案例通过。

## 最值得展示的工程过程

1. **没有用开发集替代泛化证据**：Planner v3 先在开发集迭代，再冻结 32 题 holdout、候选系统和门槛；最终结论保持为“无退化”，默认 direct 不变。
2. **没有用改标签掩盖资料缺口**：PyPDFLoader metadata badcase 通过补充固定官方源码、构建新索引和 required release cases 修复，历史 benchmark 保持不变。
3. **没有因为模型更大就默认启用**：cross-encoder 在固定候选上未提高总体 nDCG且增加延迟，因此只保留为可选能力。
4. **没有把安全只写在 prompt 里**：危险请求前置终止，证据视为不可信数据，安全结果并入发布门槛。
5. **没有直接覆盖活动索引**：增量构建、候选验证、原子切换和 rollback 组成完整生命周期。

## 诚实边界

- qrels 主要是隐藏系统与排名后的 LLM 盲标，并经过小规模辅助抽查，不是生产级人工金标。
- 独立 holdout 规模为 32 题，覆盖当前 RAG 工程知识域，不代表跨行业泛化。
- 本地生成模型存在格式波动，检索质量和答案生成质量分开评估。
- 确定性安全规则提供工程底线，不替代开放域内容安全或权限系统。
