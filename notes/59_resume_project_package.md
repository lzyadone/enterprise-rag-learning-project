# 简历项目包装

## 目标

将现有 Enterprise RAG Learning Project 转换成招聘方可快速阅读、候选人也能在面试中解释清楚的项目经历，同时保持指标口径真实，不把个人学习项目包装成虚构的生产项目。

## 交付内容

- 新增 `docs/portfolio/resume_project.md`。
- 提供可直接用于一页中文简历的推荐版和空间不足时的极简版。
- 为 AI 应用/RAG、Python 后端、数据/搜索工程三个方向提供针对性改写。
- 提供 60 秒面试自我介绍、三个 STAR 风格重点案例和高频追问回答。
- 整理可放入专业技能区的技术关键词，并列出容易夸大的错误表述及诚实改写。
- 增加投递前检查清单和仓库内证据入口。
- 将简历材料接入根 README、作品集入口和文档自动检查。

## 指标表达边界

- `Recall@10 1.000` 明确限定为冻结的 32 题 holdout，不描述成开放场景准确率。
- `12.67x` 明确限定为 embedding 已预热、同进程重复检索的热缓存微基准，不描述成页面端到端性能。
- Planner v3 的独立结论保持为“无退化并进入实验模式”，不描述成显著质量提升。
- 项目定位为使用企业级工程方法的个人学习与作品集项目，不虚构公司、客户、生产用户或商业收益。
- qrels、安全规则、单进程缓存和本地生成模型的当前边界均在面试材料中明确说明。

## 验证结果

- `python -m unittest tests.test_portfolio_docs`：4 项通过。
- 统一质量门槛：依赖检查、Python 编译、139 项测试、8/8 安全案例和 JavaScript 语法检查全部通过。
- 文档相对链接、Markdown 围栏和关键主题检查通过。
- 未加入密钥、token、环境变量值或 `.env` 内容。

## 结论

项目现在拥有从仓库证据到简历 bullet、面试自述和技术追问的完整表达链路。候选人应根据目标岗位选择 4-5 条内容，并只保留自己能够解释原理、实验口径和设计取舍的部分。
