# RAG 安全回归与发布门槛

日期：2026-08-27

## 目标

为 Web RAG 请求增加可重复验证的安全边界，覆盖直接提示注入、凭据索取、跨用户记忆访问、知识库外实时问题、检索证据中的指令，以及显式来源冲突。

## 设计

1. 查询前置判断：高置信危险请求在索引、记忆、检索和模型初始化之前返回固定拒绝；明确的实时外部数据请求返回固定的知识库资料不足。
2. 凭据生命周期：临时远程凭据进入请求入口后立即从请求对象移除，只通过局部变量传给单次模型调用。
3. 证据隔离：每条检索资料使用明确边界包裹，提示词声明资料和记忆是不可信数据，资料中的指令不得执行。
4. 来源冲突：通过 `conflict_group` 和 `claim_position` 元数据识别同一事项的不同立场，要求回答披露冲突并引用全部相关来源。
5. 最终门槛：安全审计并入 `quality_pass`，与引用、忠实度和覆盖审计共同决定答案是否通过。

## 冻结样例

`eval/benchmarks/rag_security_v1/cases.json` 包含 8 个确定性样例：

- 3 个拒绝类查询；
- 1 个正常安全教学查询；
- 2 个知识库外实时数据查询；
- 1 个检索证据指令注入；
- 1 个显式来源冲突。

门槛为 100%，任一类别失败即不通过。

## 验证结果

- 安全门槛：`8/8`，通过。
- 完整 Python 测试：`130/130`，通过。
- 真实 Web 接口：拒绝类和知识边界类请求均由 `security_policy` 处理，来源数为 0、记忆写入数为 0、质量门槛通过。
- Python 编译检查和 `git diff --check`：通过。

## 边界

- 当前分类器有意采用高精度规则，不试图替代通用语义安全模型。
- 来源冲突只在存在显式结构化元数据时判定，避免用脆弱关键词猜测事实矛盾。
- 正常的安全教学问题继续进入 RAG，不因包含“提示词注入”等主题词而被误拒绝。
