# 面向外部读者的项目介绍优化

## 目标

优化招聘方和首次访问仓库的读者最先看到的项目介绍，减少内部版本名、实验模式名和流程术语，让读者先理解项目解决的问题、核心能力和验证结果，再按需进入技术证据层。

## 修改范围

- 根 `README.md` 顶部项目简介、项目概览、核心能力和架构图节点。
- `docs/portfolio/README.md` 的项目结论、工程过程、指标名称和诚实边界。
- `docs/portfolio/resume_project.md` 的简历推荐版、极简版、岗位改写、60 秒自述、面试案例和指标边界。
- `tests/test_portfolio_docs.py` 的外部文案术语检查。

历史实验章节、阶段笔记和证据链接保留原始版本名称，不覆盖或改写既有实验结论。

## 表达规则

| 内部表达 | 对外表达 |
|---|---|
| planned v3 / Planner v3 | 受约束的复杂问题拆解 |
| direct / planned / auto | 稳定默认路径 / 可选复杂问题处理 / 自动策略 |
| oracle agreement | 自动策略与逐题最佳策略一致率 |
| retrieval runs | 单问题检索任务数 |
| holdout | 冻结的独立测试集 |
| qrels | 相关性标签 |

对外文案不隐藏技术事实，只把过程代号转换成读者能够直接理解的能力、原因和结果。

## 验证结果

- 文档自动检查：4/4 通过。
- 简历核心区域不包含 `planned v3`、`Planner v3`、`oracle`、`retrieval runs` 或 `direct/planned/auto`。
- 统一质量门槛复验通过：139 项测试、8/8 安全案例和 JavaScript 语法检查全部通过。
- 首次完整门槛中一个索引内容漂移测试临时失败，单项复验通过，第二次完整门槛 139/139 通过；本阶段未修改索引代码或数据。
- 未加入密钥、token、环境变量值或 `.env` 内容。

## 结论

项目现在形成两层表达：README、作品集首页和简历负责让外部读者快速理解；指标文档、实验记录和源码负责提供可追溯证据。后续新增优化时，应先描述解决了什么问题和产生了什么结果，再在证据层记录内部版本名。
