# 项目更名与简历两段式格式

## 目标

将面向招聘方的项目名称从课程/学习项目风格调整为清晰的产品化名称，并把简历核心经历从五条项目符号压缩为一到两段连续文字，通过加粗主要技术提高快速扫描效率。

## 项目名称

- 中文展示名：`企业级智能知识库与问答平台`
- 英文展示名：`Enterprise Knowledge Intelligence Platform`
- GitHub 仓库名暂时保持 `enterprise-rag-learning-project`，避免现有链接失效。

新名称已同步到根 README、零基础指南、作品集首页、简历材料和交接文档。内部源码路径、实验目录与历史提交不做机械重命名。

## 简历格式

- 推荐版使用两段正文，不再使用五条项目符号。
- 第一段说明知识处理、混合检索、复杂问题拆解和独立评测。
- 第二段说明版本化索引、Web 工作台、模型接入、安全与持续质量检查。
- 极简版压缩为一段，适合简历空间有限时使用。
- 不单独罗列技术栈；主要技术在正文首次出现时直接使用 Markdown 加粗，包括 Python、bge-m3、Chroma、BM25、RRF、Ollama、OpenAI-compatible API、unittest 和 GitHub Actions。

## 自动检查

文档测试新增以下约束：

- 推荐版不得重新出现以 `- ` 开头的项目符号。
- 推荐版不得出现独立的“核心技术”列表。
- Python、Chroma、BM25、RRF、Ollama 和 GitHub Actions 必须保留加粗标记。
- 原有的相对链接、文档结构、指标和外部术语约束继续生效。

## 验证结果

- 文档检查：4/4 通过。
- 统一质量门槛：139 项测试、8/8 安全案例和 JavaScript 语法检查全部通过。
- 对外文档中不再出现旧展示名称。
- 未加入密钥、token、环境变量值或 `.env` 内容。

## 结论

项目对外名称现在更接近可交付的平台，而不是课程练习；简历推荐版也更适合在有限版面中连续阅读和快速识别技术关键词。
